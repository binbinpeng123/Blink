# 已知限制

本文件记录 Blink 在开发过程中**刻意接受或无法验证**的限制。目的是避免把未验证的能力描述成已交付功能。每条限制都注明来源（设计决策或环境约束）与当前状态。

最后更新：2026-10-23

## 设计决策导致的限制

| 限制 | 原因 | 影响 |
| --- | --- | --- |
| **单节点，无复制、无容错** | 首个版本范围明确排除分布式 | 单节点磁盘故障即数据丢失。生产部署必须自行做备份 |
| **不实现纠删码** | 单节点收益小、复杂度高 | 无空间效率优化；容量管理依赖磁盘水位 |
| **元数据为每对象 JSON 文件** | 换取可读性与可调试性 | **LIST 需读取全部元数据，对象数量大时延迟上升。这是当前主要性能风险** |
| **对象目录名为 key 的 SHA256** | 避免非法字符与路径攻击 | 无法通过目录名直接辨认对象，排查需读取 `meta.json` |
| **写入时校验、读取时默认不校验** | 零拷贝读与校验读原理冲突，优先保障模型加载吞吐 | 静默损坏只能在后台 scrub 或显式开启校验读时发现 |
| **删除对象后空间可能不立即释放** | 内容寻址去重共享块 + GC 宽限期 | 用户可能误以为删除未生效；需通过可回收空间指标解释 |
| **重复内容不重复占用磁盘** | 内容寻址的天然结果 | 空间释放语义不是"一对象一份空间"，与部分用户直觉不符 |
| **不支持批量删除、ACL、Tagging、Lifecycle、Versioning、Replication、Object Lock** | 首个版本范围外，显式返回 `501` | 依赖这些特性的客户端或脚本会失败（但错误明确） |
| **Range 不支持多区间** | 简化实现，S3 客户端极少使用 | 多区间请求返回 `501` |
| **分片下载（`partNumber=N`）未实现** | 简化；主流客户端用 Range 而非该参数 | 显式返回 `501` |
| **启动时不做 CAS 全盘完整性扫描** | 保证启动代价与对象数量弱相关 | 已损坏但未被访问的块不会在启动时被发现 |
| **首个版本仅支持 HTTP** | 安全体系属 06 文档范围，尚未评审 | 不得用于生产环境；生产部署必须等待 TLS 与认证策略定稿 |

## 待确认的设计决策

| 项 | 当前实现 | 待确认 |
| --- | --- | --- |
| 满盘响应码 | `503 SlowDown` | `503`（AWS 风格，SDK 内建退避）vs `507`（语义更精确），在 04 文档定稿时确认 |
| 满盘时 `/readyz` 行为 | 保持 `200`，仅暴露水位字段 | 若改为 `503`，Kubernetes 会摘除流量，使"满盘仍可读可删"失效。需与 04 文档的 `readinessProbe` 一并确认 |

## 记录规则

- 任何新增限制必须在实现该功能时同步写入本文件。
- 限制被解除时，必须同时更新此处状态与对应的评审文档，并附验证证据。
- 不得因为"暂时做不到"而删除条目；应保留并注明原因。
