# 已知限制

本文件记录 Blink 在开发过程中**刻意接受或无法验证**的限制。目的是避免把未验证的能力描述成已交付功能。每条限制都注明来源（设计决策或环境约束）与当前状态。

最后更新：2026-11-08

## 环境约束导致的未验证项

| 限制 | 来源 | 状态 |
| --- | --- | --- |
| **MinIO Client (`mc`) 互操作未测试** | 开发环境未安装 `mc`，且当前无法安装 | 未验证。05 文档要求的 `mc` 测试标记为待补充。**不得声称通过** |
| **真实掉电场景未测试** | macOS 无法可靠模拟掉电 | 未验证。已由故障注入覆盖"fsync 后 rename 前"关键窗口，并有 8 轮 SIGKILL 崩溃测试；**真实掉电行为未知，不得声称已测** |
| **SIGKILL 后留下 `.tmp-*` 孤儿文件** | 临时文件必须与目标同目录（跨目录 rename 会退化为复制），启动清扫只处理 `tmp/` 目录 | 不影响正确性（孤儿文件永远不被引用），但会积累垃圾。实测：8 次 SIGKILL 留下 3 个。需运维周期清理，后续在 GC 中一并回收 |
| **Kubernetes / K3s 实际部署未测试** | 开发环境无 `k3s`，当前 `kubectl` 上下文指向共享集群（不可用于实验） | 未验证。已完成 `kubectl apply --dry-run=client`、Podman 本地构建与容器冒烟（健康端点、S3 往返、重启后数据保留、`--read-only` + 256 MiB 限制下启动）；**安装、滚动升级、卸载与 `local-path` 绑定均未执行** |
| **镜像构建依赖可访问的基础镜像仓库** | 本机 Docker Hub 不可达（`registry-1.docker.io` 超时），Podman 虚拟机可访问镜像站 | 已用 `GO_IMAGE=docker.m.daocloud.io/library/golang:1.27-alpine` 构建成功；默认仍指向 `golang:1.27-alpine` |
| **真实硬件性能未测量** | 尚无目标边端设备 | 未验证。现有数字仅为本机回归基线 |
| **跨平台文件系统语义差异未验证** | 仅在 macOS/APFS 上开发 | 未验证。`F_FULLFSYNC` 语义与 Linux 不同，性能与崩溃行为可能不同 |
| **1 KiB PUT P50 < 2 ms、64 并发 1 MiB PUT > 300 MB/s 在本机不可达** | APFS `F_FULLFSYNC`：单次 write+fsync ≈ 4.0 ms、rename+dirsync ≈ 8.1 ms，一次 PUT 至少 2+2 次；设备层串行化使并发无法转化为吞吐 | 实测 14.0–18.4 ms 与 97–104 MB/s（09 文档）。**Linux/NVMe 是否可达未验证，不得外推，也不得因此下调 05 文档目标** |
| **16 MiB 对象写入受 MD5 计算上限约束** | ETag 必须在写 meta 前算出；本机 `crypto/md5` 约 250 MB/s | 实测 16 MiB PUT 64–69 ms、242–262 MB/s。并行块写入实测无收益已回滚；更高吞吐需重新设计 ETag 计算时序并另设基准 |
| **签名分块（`STREAMING-AWS4-HMAC-SHA256-PAYLOAD[-TRAILER]`）未用真实客户端验证** | aws-cli 2.36.2 在 HTTPS 下实测只发送未签名流式载荷（`STREAMING-UNSIGNED-PAYLOAD-TRAILER`） | 签名分块已实现，并用独立 Python 实现生成的签名向量单测覆盖（含 trailer 签名）；但**没有真实客户端走过该路径，不得声称互操作已验证**。未签名流式上传（PutObject 与 UploadPart）已用 aws-cli 实测通过 |
| **TLS 仅以自签证书 + `--no-verify-ssl` 验证** | 无生产 CA、无证书轮换机制 | 服务端 TLS 1.2+ 已验证可启动并完成上传/下载；**客户端信任链、证书续期与生产 CA 场景未验证** |

## 设计决策导致的限制

| 限制 | 原因 | 影响 |
| --- | --- | --- |
| **单机模式（默认）无复制、无容错** | v0.1.0 范围排除分布式；v0.2.0 增加集群模式但仍默认 `single` | 单机部署下磁盘故障即数据丢失。v0.2.0 起可通过 `BLINK_CLUSTER_MODE=cluster` 获得多副本/EC，见下文"分布式模式" |
| **纠删码默认关闭** | v0.1.0 不实现；v0.2.0 自研 GF(2^8) 柯西 RS，默认 `BLINK_EC_ENABLED=false` | 默认仍无空间效率优化；开启后需全集群同版本二进制，且滚动升级期间必须关闭 |
| **元数据为每对象 JSON 文件** | 换取可读性与可调试性 | **LIST 需读取全部元数据，对象数量大时延迟上升。这是当前主要性能风险。**切片 9 已落地分片并行扫描与部分字段解码，本机 10 万对象 LIST 从 17.8 s 降到 4.1 s（Apple M4/APFS，仅回归基线）；仍远未达到 05 文档 "< 500 ms" 的目标，小对象 needle 打包（创新 D）继续延后 |
| **对象目录名为 key 的 SHA256** | 避免非法字符与路径攻击 | 无法通过目录名直接辨认对象，排查需读取 `meta.json` |
| **写入时校验、读取时默认不校验** | 零拷贝读与校验读原理冲突，优先保障模型加载吞吐 | 静默损坏只能在显式开启校验读或跑 scrub 时发现。**可用状态**：`--verify-read` / `BLINK_VERIFY_READ` 已实现并接入启动参数（默认关闭，打开后逐块 CRC32C 校验，代价是失去 sendfile 零拷贝）；`store.ScrubObject` 已实现块级校验与坏块定位，但**尚无定时调度器或 HTTP 管理入口**，目前只能由代码调用 |
| **删除对象后空间可能不立即释放** | 内容寻址去重共享块 + GC 宽限期 | 用户可能误以为删除未生效；需通过可回收空间指标解释 |
| **重复内容不重复占用磁盘** | 内容寻址的天然结果 | 空间释放语义不是"一对象一份空间"，与部分用户直觉不符 |
| **不支持 ACL、Tagging、Lifecycle、Versioning、Replication、Object Lock** | 首个版本范围外，显式返回 `501` | 依赖这些特性的客户端或脚本会失败（但错误明确） |
| **CopyObject 单次上限 5 GiB；更大对象须走 `UploadPartCopy`** | 与 S3 单次复制契约一致；分片复制在切片 11 实现，单分片上限同为 5 GiB | 源对象 > 5 GiB → `400 InvalidRequest`；客户端可用 `UploadPartCopy` 按 ≤5 GiB 区间复制。**aws-cli 2.36.2 的 `s3 cp s3://… s3://…` 默认 `--copy-props default` 会先调用 `GetObjectTagging`（本版本 `501`），因此大对象服务端复制必须加 `--copy-props none`** |
| **单机模式不能复制 EC 布局的源对象** | 单机路径复制只搬运元数据，无法保证目标节点上存在对应分片 | 返回 `501 NotImplemented`。集群模式走流式重写，不受此限制 |
| **集群 CopyObject 不是零拷贝** | 目标副本需按目标 key 的环位置重新分布，数据必须经协调者流式读一次、写一次 | 耗时与对象大小线性相关。**O(1) 元数据复制只对单机模式成立**，文档与响应均不得宣称集群复制零拷贝 |
| **CopyObject 的条件检查与写入非原子** | 源条件在读取源后求值，目标 `If-None-Match: *` 在写入前检查，期间无全局锁 | 并发复制到同一目标时，条件可能被同时满足（与集群条件写的"尽力而为"同源）；单客户端顺序操作不受影响 |
| **DeleteObjects 单次最多 1000 个对象** | 与 S3 契约一致，防止单请求占用过多 worker 与内存 | 超过 1000 或 XML 非法 → `400 MalformedXML`；更大批量需客户端分批 |
| **Range 不支持多区间** | 简化实现，S3 客户端极少使用 | 多区间请求返回 `501` |
| **分片下载（`partNumber=N`）只对分片上传对象生效** | 边界来自 Complete 时写入 `meta.json` 的 `parts`；`PutObject`/`CopyObject` 不产生该字段 | 非分片对象 `partNumber=1` 返回 `200` 整对象，`partNumber>1` → `416 InvalidPartNumber`；复制后的对象不保留源分片边界 |
| **启动时不做 CAS 全盘完整性扫描** | 保证启动代价与对象数量弱相关 | 已损坏但未被访问的块不会在启动时被发现 |
| **TLS 默认不启用，且安全体系未定稿** | TLS 需显式配置证书/私钥；认证策略属 06 文档范围，尚未评审 | 默认仍以 HTTP 启动；即使启用 TLS，也不得用于生产环境，须等待 06 文档的认证与密钥管理定稿 |

## 分布式模式（v0.2.0）的已知限制

下表条目在 08 文档评审通过、对应切片的验收完成后逐项回填状态。在此之前，任何一条都**不得声称已验证**。

| 限制 | 原因 | 影响 |
| --- | --- | --- |
| **无自动再平衡与在线成员变更** | 静态成员表，无发现、无共识 | 扩缩容必须离线执行 `blink-admin rebalance`；运行中改 peers 不保证数据移动 |
| **无节点发现 / 无共识（Raft 等）** | 保持轻量，面向边端固定拓扑 | 成员表靠配置文件维护；配置漂移会导致请求落到不存在的节点 |
| **条件写为尽力而为** | 并发协调者下无全局串行化 | `If-None-Match: *`/`If-Match` 在跨节点并发时不严格等价于 AWS 的强串行化 |
| **失败写可能部分生效** | 写扇出后不足 W 就返回 5xx，但成功的副本已落盘 | 客户端重试必须幂等；与 S3 行为一致，但需在客户端侧注意 |
| **集群 LIST 成本约 O(节点数 × 对象数)** | 每节点扫本机 `meta.json` 后归并 | 不承诺 05 文档的单机 `<500ms`；节点数上限建议 12 |
| **内部端口为明文 HTTP** | 不引入 mTLS，降低边端证书运维负担 | 9100 只能部署在内网/同 namespace；跨不可信网络必须自行加隧道或反代 |
| **EC 丢失超过 m 个永久节点后无法重建** | 无自动换组重编码 | 需人工恢复节点或从备份重建；不得把 EC 当作无限容错 |
| **EC / 副本混合版本不兼容** | 旧二进制无法解释 `layout:"ec"` 的 meta | 集群升级必须同版本；滚动升级期间关闭 EC |
| **K8s 集群部署未实测** | 无隔离多节点开发集群；共享 ACK 集群只允许 `--dry-run=client` | headless DNS、`volumeClaimTemplates`、NetworkPolicy 均未在真实集群验证；仅本机多进程模拟 |
| **真实网络分区 / 跨主机时钟偏差未测** | 本机多进程模拟无法复现 | 分区下的行为（部分提交、tombstone 竞争）只有单测与代码审查支撑 |
| **块 GC 仍未实现** | 与单机一致的既有取舍 | 集群模式下删除只删 meta/tombstone，CAS 块不回收；空间占用为副本数的倍数 |

## 已确认的协议语义（2026-10-26）

以下两项曾标注为"待确认"，现按主流实现的行为定稿：

| 项 | 决定 | 依据 |
| --- | --- | --- |
| 满盘响应码 | `507 InsufficientStorage`，已由 HTTP 层测试端到端验证（写入 507、读取 200、删除 204、腾出空间后恢复） | MinIO 返回 `507 XMinioStorageFull`，Dell ECS/ObjectScale 返回 `507 InsufficientStorage`；AWS 的 `503 SlowDown` 表示**请求限流**（"Please reduce your request rate"），不是容量耗尽。507 仍是 5xx，SDK 退避重试仍生效，但错误码明确要求扩容或删除数据 |
| 满盘时 `/readyz` 行为 | 保持 `200`，仅暴露水位字段 | 主流健康检查不把容量耗尽等同于进程未就绪，容量应单独监控。若返回 `503`，Kubernetes 会摘除唯一实例，使"满盘仍可读可删"失效，用户失去自救途径 |

## 记录规则

- 任何新增限制必须在实现该功能时同步写入本文件。
- 限制被解除时，必须同时更新此处状态与对应的评审文档，并附验证证据。
- 不得因为"暂时做不到"而删除条目；应保留并注明原因。
