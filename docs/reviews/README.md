## 当前进展

首个实现切片（v0.1.0）的范围为 01、02、03、05 四份文档，实现分支 `feature/core-storage`。

- 04 文档定稿前需要确认两个参数：满盘响应码、满盘时 `/readyz` 行为（见 `docs/design/known-limitations.md`）。
- 06 文档定稿前，开发环境仅使用本地测试凭据，**不得作为生产部署依据**。
- 环境约束导致的未验证项集中记录在 [`docs/design/known-limitations.md`](../design/known-limitations.md)。

## 推荐评审顺序

建议按以下顺序允许开发：

1. `01-product-scope.md`
2. `02-s3-api-contract.md` 和 `03-storage-engine.md`
3. `05-test-and-benchmark.md`
4. `04-kubernetes-deployment.md`
5. `06-security-operations.md`
6. `07-release-compatibility.md`

第一个实现切片建议先完成 01、02、03、05 四份文档的评审。未完成安全评审前，开发环境可以使用本地测试凭据，但不得作为生产部署依据。

## 评审记录规则

每份文档获准后，在文档顶部补充以下信息：

```text
评审状态：已允许开发
评审人：<GitHub 用户名或姓名>
评审日期：<YYYY-MM-DD>
适用版本：<版本或里程碑>
```

如果设计发生变化，应先更新文档和评审记录，再修改实现；测试结果、性能数据和部署结果应回填到相应文档或关联的 PR 中。
